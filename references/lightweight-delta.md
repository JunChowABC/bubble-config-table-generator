# 轻量增量交付模式

轻量增量模式用于“测试配置、快速验证、只看本次新增行”等明确场景。它不是完整依赖副本，不能直接替代正式导表输入；正式交付或用户要求拿来即导时，使用完整副本模式。

## 输出结构

- 一个主功能工作簿，集中本功能新增的全部业务 Sheet。
- 每个被引用的既有工作簿输出一个 `*_增量.xlsx`，只保留本次实际涉及的原属 Sheet、前 6 行协议头、本次新增/修改行和 `END`。
- `generation-manifest.json` 增加：
  - `delivery_mode: "lightweight_delta"`；
  - `merge_required: true`；
  - `merge_instruction`；
  - 依赖条目的 `delivery_action: "delta_created"`、`copy_scope: "delta_rows_only"`、`source_path`。

## 样式继承硬约束

增量文件不能用空白 `openpyxl.Workbook()` 重新建表后手工仿样式。必须从源工作簿派生，保留：

- `xl/styles.xml`、主题和相关工作簿级样式资源；
- 原 Sheet 名、协议头、字段顺序、导出标记和类型；
- 列宽、隐藏列、冻结窗格、行高、边框、填充、字体和第 7 行样式；
- 目标 Sheet 的页面、视图和导出相关设置。

允许裁掉未涉及的历史 Sheet 和历史数据，但不得改变目标 Sheet 的格式语义。生成后至少比较源/增量包的 `styles.xml`、主题、前 6 行和第 7 行样式 ID。

## 合并规则

1. 按 manifest 的 `source_path` 找到源工作簿。
2. 按同名 Sheet、B 列 ID 读取增量行。
3. 新 ID 追加到源表 `END` 之前；旧 ID 不得默认覆盖，必须显式声明 `updated` 并记录差异。
4. 合并后重新保存、回读和导出验证；不要把增量包直接当作包含完整依赖的正式包。

## QA 规则

- 增量专项 QA：检查协议头、ID、数组、语言引用、直接/数组外键、测试行相对源表确实新增或修改。
- 样式 QA：检查样式包和目标 Sheet 格式继承，避免新建默认皮肤。
- 通用 QA 可以只针对主表和增量文件运行；源表已有错误单独作为基线统计，不得误报为本次增量错误。
- 完整副本专用的“保留源工作簿全部 Sheet”检查不适用于 `lightweight_delta`，应改为检查目标 Sheet 存在、源路径有效和合并规则完整。

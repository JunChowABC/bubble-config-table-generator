# 缺省测试数据设计

当策划案缺少部分或全部数值时使用本文件。缺数值本身不是阻塞；AI 应构造可运行的测试配置，并把不确定性显式化。

## 来源优先级

| 标记 | 来源 | 选择方法 |
|---|---|---|
| S | 策划案明确值 | 原样使用；若与 Schema 或合法范围冲突则报告 |
| T | 当前项目配置 | 优先同字段、同模块、相邻正式行；取中位量级、众数、常见区间或代表组合 |
| D | 规则推导 | 使用公式、上下限、单位、依赖关系、守恒关系和业务不变量 |
| A | AI 测试假设 | S/T/D 均不足时使用最小可行假设；必须说明理由、预期和风险 |

来源是逐字段记录，不是只给整行一个标签。一个测试行可以同时包含 S、T、D、A。

## 生成矩阵

每个功能至少覆盖：

1. 正常值：位于项目现有中位量级，能走通主流程。
2. 边界值：最小合法值、最大合法值、0/空分支、`min=max` 等，只选字段确实允许的边界。
3. 分支值：每个枚举、状态或 `type + param` 结构至少一条。
4. 联动值：条件→消耗→奖励/掉落→物品、任务→文本/跳转等必要链路可完整执行。
5. 负向值：重复 ID、缺失外键、错误 JSON、越界概率等只能进入非导出区。

## 数值构造方法

- ID：读取 B1 规则和当前占用段，分配候选合法 ID；测试 ID 也不能随意使用 `max+1`。
- 整数数量：正常值取同列常见正数；边界取最小合法正数和注释允许的上限。
- 概率：先确定是万分比、百分数还是小数系数，再分别使用低/中/满量级测试点。不得默认所有概率都是 10000 制。
- 权重：使用不相等的相对权重并记录预期比例；只有注释明确时才要求总和为固定值。
- 时间：先确定秒、毫秒、分钟、小时、自然日或时间点数组；正常值沿用同列量级，边界覆盖立即/最短/较长但合法情形。
- 金额与价格：确认分、元、金币或其他货币；测试值以验证流程为主，不据此声明经济平衡。
- 倍率：确认 100、10000 或小数系数语义，避免重复换算。
- 最小/最大：满足 `min <= max`，至少有一组 `min=max`（若合法）和一组正常区间。
- 数组：覆盖空数组（仅当明确允许）、单元素、多元素和必要的嵌套结构；全部使用严格 JSON。
- 外键：只引用已存在目标 ID；缺少依赖时同步生成测试依赖行。
- 文本：玩家可见测试文案先生成 `tlanguage_cn` 条目，再写业务表语言 ID；有占位符时验证数量、顺序和类型。

## 标记与报告

- AI 设计行 A 列写 `测试_假设_<用途>`。
- 交付状态写“测试假设，可运行，待策划确认”。
- 每个字段记录：值、S/T/D/A、证据表/字段或推导式、测试意图、预期结果、风险。
- 如果单位或合法分支无法从策划案、表头、相邻数据和代码中确定，在非导出测试 Sheet 给出候选组合并列为待确认，不能污染正式导出区。
- 测试假设转为正式值前，必须由策划重新确认经济、难度、商业化、活动和用户体验影响。
